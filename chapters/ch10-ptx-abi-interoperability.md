# Chapter 10: PTX Writer's Guide to Interoperability (ABI)

## Core Idea
For PTX generated by *different* producers to interoperate, everyone must agree on the **ABI**: fundamental type sizes/alignments, aggregate/bit-field layout, the function calling sequence, system calls, atomics, and debug info. This chapter is the contract a PTX producer must honor.

## Frameworks Introduced
- **Fundamental type contract**: every PTX producer must use the exact sizes/alignments below or PTX won't be compatible. Pointer size follows the host ABI (32-bit on 32-bit host, 64-bit on 64-bit host), **but local and shared addresses are always 32 bits**. The `.address_size` directive declares the address size; the linker rejects objects built for incompatible host platforms.
- **Aggregate & union layout rules**: aggregate aligned to its most strictly aligned member; native vectors have special alignment (odd #elements → `alignof(t)`; even → `n*alignof(t)`); members placed at lowest aligned offset (internal padding); total size padded up to the aggregate's alignment (tail padding).
- **Bit-field rules** (little-endian GPUs): allocated right-to-left (LSB first); must fit entirely within a storage unit (never cross a unit boundary); may share a unit with other members; plain bit fields are **signed**; untyped width defaults to `int`; zero-length bit fields force the next member to the type's alignment boundary.
- **Function calling sequence**: PTX-level register usage, stack-frame layout, and parameter passing — an abstraction; most concrete detail is handled at **SASS** level.
- **Opaque objects (texture/sampler/surface)**: `.texref`/`.samplerref` (textures, accessed via `TEX`), `.surfref` (surfaces, via `SULD`/`SUST`). Attributes live in a driver-populated descriptor (queried via `TXQ`/`SUQ`); the descriptor format is architecture-specific — **do not rely on it**. When the reference is unknown at compile time, a `.b64` **handle** carries all needed info and can be passed to/from functions.
- **System Calls, Atomics ABI, Debug Information**: standardized so mixed-producer PTX links and debugs correctly.

## Key Concepts
- **ABI**: binary contract for type layout + calling convention enabling interop.
- **`.address_size`**: directive declaring PTX address width.
- **handle (`.b64`)**: runtime reference to an opaque texture/sampler/surface object.
- **SASS**: the architecture-specific machine ISA below PTX.
- **little-endian**: current GPUs only support little-endian memory.

## Reference Tables
PTX fundamental scalar types (size / align in bytes):
| PTX Type | Size | Align | Meaning |
|---|---|---|---|
| .b8/.s8/.u8 | 1 | 1 | byte (untyped/signed/unsigned) |
| .b16/.s16/.u16 | 2 | 2 | halfword |
| .b32/.s32/.u32 | 4 | 4 | word |
| .b64/.s64/.u64 | 8 | 8 | doubleword |
| .f16 | 2 | 2 | IEEE half |
| .f32 | 4 | 4 | IEEE single |
| .f64 | 8 | 8 | IEEE double |

Bit-field widths:
| Type | Width w | Range |
|---|---|---|
| signed char | 1–8 | -2^(w-1) … 2^(w-1)-1 |
| unsigned char | 1–8 | 0 … 2^w-1 |
| signed/unsigned short | 1–16 | (as above) |
| signed/unsigned int | 1–32 | (as above) |
| signed/unsigned long long | 1–64 | (as above) |

Opaque object types:
| PTX type | Represents | Access instructions |
|---|---|---|
| `.texref` | texture | `TEX`, `TXQ` |
| `.samplerref` | sampler | `TEX` |
| `.surfref` | surface | `SULD`/`SUST`, `SUQ` |

## Key Takeaways
1. Honor the exact PTX type sizes/alignments or PTX won't interoperate.
2. Local & shared addresses are always 32-bit, regardless of host pointer size.
3. Aggregates/bit-fields follow precise layout rules; GPUs are little-endian.
4. Function calling sequence is a PTX abstraction; the real ABI detail is at SASS level.
5. Opaque texture/surface objects use driver descriptors and `.b64` handles — never depend on descriptor internals.
