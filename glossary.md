# Glossary — CUDA Programming & PTX

**ABI** — binary contract (type layout, calling convention) enabling PTX/object interoperability (Ch 10)
**address_size (`.address_size`)** — PTX directive declaring the address width used in the code (Ch 10)
**architecture-specific feature** — capability (CC ≥ 9.0) not guaranteed on later architectures; runs only on its exact compute capability (Ch 12)
**array (tile model)** — mutable multidimensional container in device memory; has shape + dtype (Ch 6)
**asm()** — inline PTX assembly statement: `asm("tmpl" : outs : ins : clobbers)` (Ch 9)
**asynchronous (launch/copy)** — returns to host before device work completes; needs later synchronization (Ch 2, Ch 7)
**atomic functions** — `atomicAdd` etc.; let blocks update a common result without a barrier (Ch 5)
**baseline feature set** — features introduced to be available on all subsequent architectures (Ch 12)
**bit field** — struct member of specified bit width; little-endian, right-to-left, must fit one storage unit (Ch 10)
**block (thread block)** — group of threads running on one SM, sharing shared memory & `__syncthreads()` (Ch 1)
**built-in variables** — `threadIdx`, `blockIdx`, `blockDim`, `gridDim`, `warpSize` (Ch 2, Ch 11)
**CCCL** — CUDA Core Compute Library; e.g. `cuda::ceil_div`, `<cuda/cmath>` (Ch 2)
**cluster (thread block cluster)** — group of blocks (CC ≥ 9.0) co-scheduled in one GPC; distributed shared memory (Ch 1)
**coalescing (memory)** — warp threads accessing contiguous global addresses → combined transactions (Ch 5)
**compute capability** — versioned feature/spec level of an SM (e.g. 9.0); a.k.a. SM version (Ch 1, Ch 12)
**constant memory (`__constant__`)** — read-only (device), cached; host-writable via runtime API (Ch 5, Ch 11)
**Cooperative Groups** — API for structured multi-granularity thread-group synchronization (Ch 8)
**cubin** — architecture-specific GPU binary (`sm_XX`) (Ch 1, Ch 12, Ch 14)
**CUDA context** — per-device runtime state (primary context); lazily created (Ch 4)
**CUDA Graph** — DAG of operations defined once and launched repeatedly (Ch 8)
**`cudaDeviceSynchronize`** — blocks host until all GPU work completes (Ch 2, Ch 7)
**`cudaMallocManaged` / `__managed__`** — unified memory allocation (Ch 3, Ch 11)
**`cudaMalloc` / `cudaMemcpy`** — explicit device alloc / synchronous copy (Ch 3)
**`cudaMallocHost`** — pinned (page-locked) host memory; required for async copies (Ch 3)
**`cudaError_t`** — enumerated return type of CUDA APIs; success is `cudaSuccess` (Ch 4)
**default stream** — implicit stream for unstreamed ops; has blocking semantics (Ch 7)
**deprecated vs dropped** — discouraged-but-present vs removed entirely (Ch 16)
**device / host** — GPU + its memory / CPU + its memory (Ch 1)
**device code** — code executed on the GPU (Ch 1)
**distributed shared memory** — shared memory of all blocks in a cluster, mutually accessible (Ch 1)
**Dynamic Parallelism** — device-side kernel launching child kernels (Ch 8)
**event (`cudaEvent_t`)** — stream marker for timing / cross-stream sync (Ch 7)
**execution configuration** — grid + block dims (+ optional cluster/stream/SM config) at launch (Ch 1, Ch 2)
**execution space specifier** — `__host__`/`__device__`/`__global__`/`__tile__`/`__tile_global__` (Ch 11)
**family-specific feature** — arch-specific feature shared across a family of CCs (CC ≥ 10.0) (Ch 12)
**fatbin** — container bundling multiple PTX + cubin targets (Ch 1, Ch 14)
**`__global__`** — kernel qualifier: host-callable, device-run, void return, async, no recursion (Ch 2, Ch 11)
**global memory** — device-wide DRAM; main data store, high latency (Ch 5)
**GPC (Graphics Processing Cluster)** — group of SMs; clusters are scheduled within one GPC (Ch 1)
**grid** — all thread blocks of a kernel launch; 1/2/3-D (Ch 1)
**handle (`.b64`)** — runtime reference to an opaque texture/sampler/surface object (Ch 10)
**JIT compilation** — driver compiles PTX → SASS at load time (Ch 1, Ch 12)
**kernel** — device function invoked on the GPU; launching starts many threads (Ch 1, Ch 2)
**matmul / mma** — tile matrix multiply / multiply-accumulate (maps to tensor cores) (Ch 6)
**memcpy_async** — async global→shared copy primitive; overlaps copy with compute (Ch 8)
**memory clobber** — `"memory"` in asm 3rd colon; stops memory reordering around asm (Ch 9)
**metapackage** — convenience package pulling in a set of CUDA components (pip/conda) (Ch 15)
**`__NV_SILENCE_HOST_DEPRECATION_BEGIN/END`** — scoped deprecation-warning suppression (Ch 16)
**nvcc** — offline CUDA compiler/toolchain driver (Ch 14)
**nvrtc** — runtime (JIT) CUDA compiler (Ch 14)
**ndarray** — CUDA Python GPU array object type (Ch 13)
**opaque object** — PTX texture/sampler/surface (`.texref`/`.samplerref`/`.surfref`) (Ch 10)
**page-locked (pinned) memory** — non-pageable host memory; faster & required for async transfers (Ch 3)
**partition_view / tiled_view** — view mapping an array into tile space (C++ / Python) (Ch 6, Ch 13)
**pinned memory** — see page-locked (Ch 3)
**primary context** — per-device context created by the runtime; shared across host threads (Ch 4)
**PTX (Parallel Thread Execution)** — forward-portable virtual ISA / IR (Ch 1, Ch 9, Ch 10)
**ptxas** — assembler: PTX → cubin for a target SM (Ch 14)
**register** — fastest, per-thread storage (Ch 5)
**SASS** — architecture-specific machine ISA below PTX (Ch 10)
**shared memory (`__shared__`)** — on-SM, per-block, low-latency memory (Ch 5)
**SIMT (Single-Instruction Multiple-Threads)** — warp execution model; threads may diverge (Ch 1)
**SM (Streaming Multiprocessor)** — GPU compute unit; runs whole thread blocks (Ch 1)
**stream (`cudaStream_t`)** — ordered work queue; separate streams enable overlap (Ch 7)
**stream capture** — record stream ops into a CUDA Graph (Ch 8)
**stream-ordered allocator** — `cudaMallocAsync`/`cudaFreeAsync` (Ch 8)
**`__syncthreads()`** — intra-block barrier (Ch 2, Ch 5)
**tensor cores** — hardware units for matrix multiply-accumulate (Ch 6, Ch 12)
**thread** — single work item; smallest execution unit (Ch 1)
**tile** — immutable, block-local, power-of-two, compile-time-shaped value collection (Ch 6)
**tile programming** — block-level model; compiler maps tile ops to threads (Ch 6)
**tile space** — array conceptually partitioned into equal non-overlapping tiles (Ch 1, Ch 6)
**triple chevron (`<<<>>>`)** — kernel launch syntax `k<<<blocks, threads, shBytes, stream>>>` (Ch 2)
**unified memory** — driver-migrated memory accessible to host & device (Ch 3)
**Virtual Memory Management** — reserve address ranges + map physical memory explicitly (Ch 8)
**volatile (asm)** — prevents compiler from moving/deleting an asm statement (Ch 9)
**warp** — 32 threads executing in lock-step (SIMT) (Ch 1)
**warp divergence** — threads in a warp taking different branches → serialized (Ch 1, Ch 5)
**WSL** — Windows Subsystem for Linux; dedicated CUDA install path (Ch 15)
